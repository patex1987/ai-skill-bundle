# AI Skill Bundle: Agent Guidance

This repository is a reusable catalog of AI-assistant skills, agents, and rules.
Read `README.md` for the model (catalog → install → `.ai/` → render → tool folders).

## Working here

- Edit canonical content only under `catalog/`, `packs/`, `routing/`, and `scripts/`.
  Never edit `imports/`: it is an archived snapshot kept for provenance.
- Keep catalog content generic. Repository paths, project names, personal host
  paths, and vendor model IDs belong in a consuming repository's
  `.ai/overlays/` or `bundle.json`, and the portability lint enforces this.
- Canonical frontmatter uses only portable fields. Tool-specific fields
  (`model`, `effort`, `disable-model-invocation`, `readonly`, TOML keys) are
  generated by `scripts/render.py`. Do not add them by hand.
- Every skill and agent needs `metadata.routing-tier`. Choose it from the
  hardest decision the entity usually involves (see `catalog/skills/model-routing`).
- When changing tool-specific rendering, check the vendor documentation and update
  `catalog/skills/model-routing/references/tool-mechanics.md` with the date checked.

## Before handing back

```sh
python3 scripts/aibundle.py validate
python3 -m unittest discover -s tests
```

Describe behaviour changes in `docs/REVIEW-LOG.md` or the PR. Installing into, or
rendering in, a real platform repository is a separate task in that repository
(its own issue, branch, and PR). Use scratch copies for experiments here.
