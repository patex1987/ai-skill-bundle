## 1. Commands/skills and the end-to-end workflow

### Takeaway
GSD is a layered prompt system: ~67 slash-command stubs (`commands/gsd/*.md`) load long workflow files (`get-shit-done/workflows/*.md`) which act as "thin orchestrators" that spawn ~33 role-specific subagents (`agents/gsd-*.md`) and call a Node CLI/SDK (`gsd-sdk query …`) for deterministic state edits. The core loop is **new-project → (discuss → [ui-phase] → plan → execute → verify-work → ship) per phase → milestone close**, with side-tracks for quick tasks, brownfield mapping, debugging, spikes/sketches, and reviews.

### Cited Findings
**Architecture layering**
- Three layers: Command layer (`commands/gsd/*.md`, YAML frontmatter + bootstrap prompt) → Workflow layer (`get-shit-done/workflows/*.md`, orchestration logic) → fresh-context Agent layer (`agents/*.md`) → CLI tools layer (`gsd-sdk query` / `gsd-tools.cjs`) → filesystem `.planning/`. — [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md)
- Design principles stated: fresh context per agent, thin orchestrators, file-based state ("No database, no server"), "absent = enabled" feature flags, defense in depth (plan-checker, atomic commits, post-exec verification, UAT). — [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md)
- Command file counts: 67 files in `commands/gsd/` (including six `ns-*` namespace routers); 33 agent files in `agents/`; workflows count ~100 files in `get-shit-done/workflows/`. — directory listings of [commands/gsd](https://github.com/gsd-build/get-shit-done/tree/bdcaab2/commands/gsd), [agents](https://github.com/gsd-build/get-shit-done/tree/bdcaab2/agents), [get-shit-done/workflows](https://github.com/gsd-build/get-shit-done/tree/bdcaab2/get-shit-done/workflows)

**The main loop (per command)**
- `/gsd-new-project` — "Initialize a new project with deep context gathering and PROJECT.md". Workflow steps (`workflows/new-project.md`): Setup → Brownfield offer → Deep Questioning → Write PROJECT.md → Workflow Preferences (writes `config.json`) → Resolve model profile → Research decision (4 parallel `gsd-project-researcher`s → `gsd-research-synthesizer`) → Define Requirements (REQUIREMENTS.md) → Create Roadmap (`gsd-roadmapper` → ROADMAP.md) → Done. — [workflows/new-project.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/new-project.md); data-flow diagram in [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md)
- `/gsd-discuss-phase <N>` — "Gather phase context through adaptive questioning before planning"; output `{phase}-CONTEXT.md`. Steps: load prior context (PROJECT/REQUIREMENTS/STATE/prior CONTEXT), scout codebase for reusable assets, identify phase-specific "gray areas", user picks which to discuss, deep-dive each. Strict scope guardrail: phase boundary from ROADMAP is fixed; new capabilities go to "Deferred Ideas". Philosophy: "User = founder/visionary. Claude = builder" — ask about vision/implementation choices, not about codebase patterns or technical risk. Modes via flags/config: `--all`, `--auto`, `--chain`, `--batch`, `--analyze`, `--text`, `--power`, `--assumptions`, and `workflow.discuss_mode: "assumptions"` (agent reads codebase first, proposes assumptions with confidence, user only corrects). — [commands/gsd/discuss-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/discuss-phase.md), [workflows/discuss-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/discuss-phase.md), [docs/CONFIGURATION.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/CONFIGURATION.md)
- `/gsd-ui-phase` (optional) — produces `UI-SPEC.md` design contract; `/gsd-ui-review` later does a 6-pillar visual audit. — [commands/gsd/ui-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/ui-phase.md), [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md)
- `/gsd-plan-phase [N]` — "Create detailed phase plan (PLAN.md) with verification loop". Default flow Research (if needed; asks user, or follows `workflow.research`) → optional pattern-mapper → Plan → Check → Revise loop (max 3). Flags: `--research`, `--skip-research`, `--research-phase <N>` (research-only), `--view`, `--gaps` (gap-closure from VERIFICATION/UAT), `--skip-verify`, `--prd <file>` (skip discuss, parse PRD into CONTEXT.md), `--ingest <ADRs>`, `--reviews` (replan from cross-AI REVIEWS.md), `--tdd`, `--mvp`, `--text`, `--chunked`. Extra gates inside plan-phase: closed-phase gate, research gate (blocks on unresolved open questions), validation (Nyquist) strategy, security threat-model gate, UI-SPEC gate, schema-push detection, requirements-coverage gate, decision-coverage gate (CONTEXT.md decisions → plans, BLOCKING), post-planning gap analysis, ROADMAP annotated with wave dependencies. — [commands/gsd/plan-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/plan-phase.md), [workflows/plan-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/plan-phase.md) (step headings §0–§15)
- `/gsd-execute-phase` — "Execute all plans in a phase with wave-based parallelization". Orchestrator discovers plans → groups by `wave` frontmatter → spawns one `gsd-executor` per plan (parallel inside a wave) → handles checkpoints → aggregates → code-review gate → regression gate → schema-drift gate → codebase-drift gate → `gsd-verifier` → update ROADMAP → learnings copy → close phase todos → update PROJECT.md → offer next. — [workflows/execute-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/execute-phase.md) (`<step name=…>` list)
- `/gsd-verify-work` — "Validate built features through conversational UAT": derives tests from SUMMARY.md files, presents one expected behaviour at a time ("yes"/empty = pass, anything else = logged issue with inferred severity), persists `{phase}-UAT.md`, then on issues **automatically** spawns parallel debug agents (root cause) and a `gsd-planner --gaps` + plan-checker loop to produce fix plans. — [workflows/verify-work.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/verify-work.md) (philosophy; steps `diagnose_issues`, `plan_gap_closure`, `verify_gap_plans`, `revision_loop`)
- `/gsd-ship` (PR + review), `/gsd-pr-branch` (filters `.planning/` commits out of a PR branch), `/gsd-undo` (safe revert via phase manifest). — [commands/gsd/ship.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/ship.md), [commands/gsd/pr-branch.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/pr-branch.md), [commands/gsd/undo.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/undo.md)
- `/gsd-autonomous` — "Run all remaining phases autonomously — discuss→plan→execute per phase"; `workflow.auto_advance` auto-chains the three; `workflow.skip_discuss` writes minimal CONTEXT.md from ROADMAP goal. — [commands/gsd/autonomous.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/autonomous.md), [docs/CONFIGURATION.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/CONFIGURATION.md)

**Milestones**
- `/gsd-complete-milestone`: pre-close audit of open artifacts; archives ROADMAP and REQUIREMENTS to `.planning/milestones/vX.Y-ROADMAP.md` / `-REQUIREMENTS.md`; overwrites ROADMAP with milestone grouping; `git rm REQUIREMENTS.md` ("fresh for next milestone"); full PROJECT.md evolution review; tags release; archives UI artifacts. **Skill-surface / token management of the command set**
- v1.40–1.41: 86 flat skills consolidated to 59 `commands/gsd/*` entries; six namespace "meta-skills" (`gsd-workflow`, `-project`, `-quality`, `-context`, `-manage`, `-ideate`) cut cold-start skill-listing overhead from ~2,150 to ~120 tokens by two-stage routing. `--minimal` / `--profile=core` install writes only 6 core skills (`new-project`, `discuss-phase`, `plan-phase`, `execute-phase`, `help`, `update`) and zero subagents, cutting cold-start prompt overhead from "~12k tokens to ~700". — [CHANGELOG.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/CHANGELOG.md) (1.41.0 "Feature" section), [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md)

### Inferences
- GSD's loop maps onto a user's research → plan → annotate → implement → validate as: research = `plan-phase` researcher (+`map-codebase`, `spike`/`explore`); "annotate" is closest to `discuss-phase` (human decisions captured *before* planning, in CONTEXT.md) plus the `--reviews`/`plan-review-convergence` cross-AI review path; there is **no first-class "human annotates the plan inline" step** in the files I read — the human gates are `gates.confirm_plan`, the discuss conversation, and checkpoints.
- Much of the surface (UI, AI-eval, security, docs, intel, profiling, etc.) is optional; the "real" core is six commands.

### Gaps
- I did not read every workflow end to end (e.g., `autonomous`, `manager`, `spike`, `sketch`); descriptions above for those come from command frontmatter only.
- Exact number of workflows not reconciled (INVENTORY.md claims an authoritative count; I counted by listing).

## 2. Artifact formats and storage (`.planning/`), and what records post-implementation state

### Takeaway
All state is Markdown/JSON under `.planning/`, per-phase files named `XX-YY-PLAN.md` / `XX-YY-SUMMARY.md` etc. Pre-implementation intent lives in PROJECT/REQUIREMENTS/ROADMAP/CONTEXT/RESEARCH/PLAN; post-implementation reality is written by the executor into **SUMMARY.md** (per plan, machine-readable frontmatter), then rolled up by CLI calls and the transition workflow into **STATE.md** (digest), **ROADMAP/REQUIREMENTS** (progress/traceability), **PROJECT.md** (Key Decisions, Validated requirements) and optionally **LEARNINGS.md**. The verifier is explicitly told *not* to trust SUMMARY.md.

### Cited Findings
**Directory layout**
- `.planning/` contains `PROJECT.md, REQUIREMENTS.md, ROADMAP.md, STATE.md, config.json, MILESTONES.md, research/ (SUMMARY, STACK, FEATURES, ARCHITECTURE, PITFALLS), codebase/ (7 docs), phases/XX-name/ (XX-CONTEXT, XX-RESEARCH, XX-YY-PLAN, XX-YY-SUMMARY, XX-VERIFICATION, XX-VALIDATION, XX-UI-SPEC, XX-UI-REVIEW, XX-UAT), quick/YYMMDD-xxx-slug/{PLAN,SUMMARY}, todos/{pending,done}, threads/, seeds/, debug/ (+resolved/, knowledge-base.md), continue-here.md`. — [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md) ("Project Files")
- Additional artifacts seen in workflows: `LEARNINGS.md` (per phase), `PATTERNS.md` (pattern-mapper), `REVIEWS.md` (cross-AI review), `HUMAN-UAT.md`, `deferred-items.md`, `SKELETON.md` (MVP walking skeleton), `AI-SPEC.md`, `SPEC.md`, `SECURITY.md`. — [workflows/execute-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/execute-phase.md), [workflows/plan-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/plan-phase.md), [agents/gsd-executor.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-executor.md), [templates/](https://github.com/gsd-build/get-shit-done/tree/bdcaab2/get-shit-done/templates)

**Pre-implementation artifacts**
- PROJECT.md template: What This Is / Core Value / Requirements (Validated, Active, Out of Scope) / Context / Constraints / Key Decisions table, plus an embedded `Evolution` rule set. — [templates/project.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/project.md)
- REQUIREMENTS.md: v1/v2/out-of-scope with REQ-IDs and a Traceability table (phase ↔ REQ status). ROADMAP.md: per-phase Goal, Depends on, Requirements, **Success Criteria ("what must be TRUE")**, Plans; decimal "INSERTED" phases (2.1). — [templates/requirements.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/requirements.md), [templates/roadmap.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/roadmap.md)
- CONTEXT.md (from discuss-phase): XML-tagged sections `<domain>` (phase boundary), `<decisions>` (numbered `D-01…` decisions plus "Claude's Discretion"), `<specifics>`, `<canonical_refs>` (specs/ADRs downstream agents MUST read), `<code_context>` (reusable assets, patterns, integration points), `<deferred>` (ideas out of scope). Consumers: researcher and planner. "Categories are NOT predefined … emerge from what was discussed." — [templates/context.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/context.md)
- RESEARCH.md written by `gsd-phase-researcher`; contains Package Legitimacy Audit table (slopcheck), Validation Architecture, optional Architectural Responsibility Map; claims tagged `[VERIFIED]`/`[CITED]`/`[ASSUMED]`; open questions must be RESOLVED or plan-phase's research gate blocks. — [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md) ("Package Legitimacy Gate"), [agents/gsd-plan-checker.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-plan-checker.md) (Dimension 11)
- PLAN.md format: YAML frontmatter `phase, plan, type (execute|tdd), wave, depends_on, files_modified, autonomous, requirements (must be non-empty), user_setup, must_haves {truths, artifacts, key_links}`; body in XML: `<objective>`, `<execution_context>` (@-refs to workflows/templates), `<context>` (@-refs to PROJECT/ROADMAP/STATE and source files), `<tasks>` with `<task type="auto|checkpoint:decision|checkpoint:human-verify|checkpoint:human-action">` each carrying `<name> <files> <read_first> <action> <verify> <acceptance_criteria> <done>`, then `<verification>`, `<success_criteria>`, `<output>` (names the SUMMARY path). Anti-shallow rules: every task MUST have `read_first`, grep/test-checkable `acceptance_criteria` (no "looks correct"), and `action` with concrete identifiers but no full implementations. — [templates/phase-prompt.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/phase-prompt.md), [workflows/plan-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/plan-phase.md) (§8 `deep_work_rules`)
- Planner sizing rule: "Plans should complete within ~50% context (not 80%) … Each plan: 2-3 tasks maximum." — [agents/gsd-planner.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-planner.md) (Quality Degradation Curve; Context Budget Rules)

**Post-implementation artifacts — how written**
- **SUMMARY.md** (`{phase}-{plan}-SUMMARY.md`), written by the executor with the Write tool after all tasks: YAML frontmatter `phase, plan, subsystem, tags, requires/provides/affects (dependency graph), tech-stack {added, patterns}, key-files {created, modified}, key-decisions, patterns-established, requirements-completed (copied from PLAN), duration, completed`; body: substantive one-liner, Performance, Accomplishments, **Task Commits (hash per task)**, Files Created/Modified, Decisions Made, **Deviations from Plan** (each auto-fix tagged `[Rule N - Type]` with found-during/fix/commit), Issues Encountered, User Setup Required, Next Phase Readiness; plus `## Known Stubs`, `## Threat Flags`, and a `## Self-Check: PASSED|FAILED` section (checks files and commit hashes exist). Template states frontmatter is designed "to enable automatic context assembly via dependency graph" so plan-phase can scan summaries cheaply. — [templates/summary.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/summary.md), [agents/gsd-executor.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-executor.md) (`<summary_creation>`, `<self_check>`)
- **STATE.md** (target <100 lines, "a DIGEST, not an archive"): Project Reference (core value, current focus), Current Position (phase/plan/status/last activity/progress bar), Performance Metrics (velocity, per-phase table), Accumulated Context (recent Decisions 3-5, Pending Todos, Blockers/Concerns prefixed by phase), Deferred Items, Session Continuity (stopped-at, resume file). YAML frontmatter holds milestone/status/progress and (newer) `active_phase`, `next_action`, `next_phases`. "Read first in every workflow; updated after every significant action." Updates are made by the executor via CLI: `state.advance-plan`, `state.update-progress`, `state.record-metric`, `state.add-decision` (decisions extracted from SUMMARY `key-decisions`), `state.add-blocker`, `state.record-session`, `roadmap.update-plan-progress`, `requirements.mark-complete`. Writes are protected by an `O_EXCL` lockfile. — [templates/state.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/state.md), [agents/gsd-executor.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-executor.md) (`<state_updates>`), [docs/STATE-MD-LIFECYCLE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/STATE-MD-LIFECYCLE.md), [docs/ARCHITECTURE.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/ARCHITECTURE.md) (Parallel Commit Safety)
- In worktree-parallel mode the executor is told "Do NOT update STATE.md or ROADMAP.md — the orchestrator owns those writes after all worktree agents in the wave complete." — [workflows/execute-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/execute-phase.md) (executor prompt in `execute_waves`)
- **VERIFICATION.md** (`gsd-verifier`): frontmatter `status: passed|gaps_found|human_needed`, `score: N/M`; tables for Observable Truths (VERIFIED/FAILED/UNCERTAIN + evidence), Required Artifacts (EXISTS+SUBSTANTIVE / STUB), Key Link Verification (WIRED/NOT WIRED), Requirements Coverage, Anti-Patterns (TODO/placeholder/console.log-only), Human Verification Required, Gaps Summary. — [templates/verification-report.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/verification-report.md)
- **UAT.md**: frontmatter `status: testing|partial|complete|diagnosed`, `source` (SUMMARYs tested); `## Current Test` overwritten each step; per-test `expected` / `result: pass|issue|skipped|blocked|pending` with verbatim user report + severity; `## Gaps` as YAML consumed by `plan-phase --gaps` (fields `truth, status, reason, severity, test, root_cause, artifacts, missing, debug_session` filled by diagnosis). Survives `/clear`. — [templates/UAT.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/UAT.md)
- **Transition / "evolve project"** (after each phase): reads phase `*-SUMMARY.md`, then edits PROJECT.md inline: move shipped Active reqs → Validated (`✓ … — Phase X`), invalidated → Out of Scope with reason, add emergent requirements, log decisions to Key Decisions, refresh "What This Is"; footer "Last updated … after Phase X". Then reviews STATE.md accumulated context (keep 3-5 recent decisions; remove resolved blockers; keep unresolved with phase prefix). — [workflows/transition.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/transition.md) (`evolve_project`, `review_accumulated_context`), [templates/project.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/templates/project.md) (`<evolution>`)

### Inferences
- CONTEXT.md is **never rewritten after implementation** (as far as I found); post-implementation divergence is captured in SUMMARY "Deviations" and "Decisions Made", then promoted to STATE (short list) and PROJECT.md (durable Key Decisions table). The durable "as-built" knowledge is therefore spread over SUMMARY (per plan), PROJECT.md (rolling), LEARNINGS.md (optional), codebase/*.md (re-mapped on drift), not one doc.
- The summaries-with-frontmatter + `history-digest` pattern is GSD's answer to "how do later phases know what earlier phases actually built" without loading everything: a structured index first, full bodies only for 2-4 relevant phases.
- Because SUMMARY.md is self-reported by the executor, GSD adds a separate adversarial verifier; the verifier's reading of real code (not SUMMARY) is the control against drift between claimed and actual state.

### Gaps
- I did not locate a step where PLAN.md or RESEARCH.md is amended post-implementation to reflect as-built reality; none seen.
- ROADMAP.md/REQUIREMENTS.md templates were read via section headings only.

## 3. Context isolation, subagents, waves, toggles

### Takeaway
Each subagent is spawned via the host's Agent/Task tool with a fresh context window (200K, or 1M on large models); orchestrators pass **file paths, not content**, and stay thin. Executors run in dependency waves (parallel within a wave, optionally in git worktrees). Context-rot is handled structurally (fresh agents, plans sized to ~50% context, STATE digest, `/clear`-survivable files) plus a context-monitor hook with warnings at 35%/25% remaining. Nearly everything is toggleable in `.planning/config.json`.

### Cited Findings

## 4. Verification: goal-backward, plan-checker loop, atomic commits, UAT

### Takeaway
Verification is layered: (a) a **pre-execution plan-checker** (adversarial, 12 dimensions, bounded 3-iteration revision loop with stall detection) that works goal-backward from phase success criteria; (b) **atomic per-task commits** plus a self-check in SUMMARY; (c) a **post-execution `gsd-verifier`** doing goal-backward must_haves checking at three levels (exists → substantive → wired) plus data-flow and behavioral spot-checks, writing VERIFICATION.md; (d) **conversational UAT** by the human, with automatic diagnosis and gap-closure planning.

### Cited Findings
**Plan-checker loop**
- `gsd-plan-checker` role: "Assume every plan set is flawed until evidence proves otherwise"; every issue must be BLOCKER or WARNING; tools limited to `Read, Bash, Glob, Grep` (cannot edit). Dimensions: 1 Requirement Coverage, 2 Task Completeness, 3 Dependency Correctness, 4 Key Links Planned, 5 Scope Sanity, 6 Verification Derivation, 7 Context Compliance (+7b scope-reduction detection, 7c architectural tier compliance), 8 Nyquist Compliance, 9 Cross-Plan Data Contracts, 10 CLAUDE.md Compliance, 11 Research Resolution, 12 Pattern Compliance. — [agents/gsd-plan-checker.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-plan-checker.md)
- Revision loop (plan-phase §12): max 3 iterations; revision prompt tells the planner to "make targeted updates … Do NOT replan from scratch unless issues are fundamental"; **stall detection** if issue count doesn't decrease (asks user: proceed anyway / adjust approach; capped at 2 re-entries, then proceed/abandon). After cap: force proceed / guidance and retry / abandon. Skippable via `workflow.plan_check: false` or `--skip-verify`. — [workflows/plan-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/plan-phase.md) (§10-12), [references/gates.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/references/gates.md) (Revision Gate)
- Gates taxonomy (`references/gates.md`): Pre-flight, Revision, Escalation, Abort gates (note: docs/ARCHITECTURE.md describes a different 4-type list, Confirm/Quality/Safety/Transition, so the docs are internally inconsistent); plan-checker implements Revision Gate, verifier implements Escalation Gate. — [references/gates.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/references/gates.md), [agents/gsd-verifier.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-verifier.md)
- Optional external refinement: `workflow.plan_bounce` pipes each PLAN.md through a user script (blocks on non-zero), and `/gsd-plan-review-convergence` loops cross-AI reviewers (Codex, Gemini, Claude, OpenCode, local models) until no HIGH concerns. — [docs/CONFIGURATION.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/CONFIGURATION.md), [commands/gsd/plan-review-convergence.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/plan-review-convergence.md)

**Atomic commits**
- Per task: stage files individually (never `git add .`/`-A`), conventional commit `{type}({phase}-{plan}): description` with bullets, record hash for SUMMARY, post-commit deletion check, untracked-file check; multi-repo via `commit-to-subrepo`; separate final docs commit `docs({phase}-{plan}): complete [plan-name] plan` for SUMMARY/STATE/ROADMAP/REQUIREMENTS (respects `commit_docs`, gitignored `.planning/`). Destructive-git prohibition section; worktree safety assertions. TDD tasks produce test→feat→refactor commits; optional MVP+TDD gate requires a `test(...)` commit before the `feat(...)` commit. — [agents/gsd-executor.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-executor.md) (`<task_commit_protocol>`, `<final_commit>`), [docs/RELEASE-v1.50.0-canary.1.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/RELEASE-v1.50.0-canary.1.md)
- `/gsd-pr-branch` creates a PR branch that filters `.planning/` commits out; `/gsd-undo` reverts by phase manifest. — [commands/gsd/pr-branch.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/pr-branch.md), [commands/gsd/undo.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/commands/gsd/undo.md)

**Goal-backward verifier**
- Core principle "Task completion ≠ Goal achievement": ask what must be TRUE → what must EXIST → what must be WIRED, then verify against actual code. Must-haves are the union of ROADMAP Success Criteria (non-negotiable; PLAN must_haves may add but never subtract) and PLAN `must_haves`; fallback derives 3-7 truths from the phase goal. Artifact check at levels: exists, substantive (not stub), wired (imported/used), plus Level 4 data-flow trace (does rendered state come from a real query?). Also key-link checks, requirements coverage (every REQ-ID in PLAN frontmatter accounted for), anti-pattern scan (TODO/placeholder/hardcoded empties/console.log-only), behavioral spot-checks (run endpoint/CLI/build/tests), probe execution. Output status `passed | gaps_found | human_needed`; each truth VERIFIED / FAILED(BLOCKER) / UNCERTAIN(WARNING). Adversarial "FORCE stance": assume goal not achieved until code proves it. — [agents/gsd-verifier.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/agents/gsd-verifier.md) (Steps 0-7c)
- Orchestrator routing on status: `passed` → update ROADMAP; `human_needed` → persist items as `{phase}-HUMAN-UAT.md` and keep phase pending; `gaps_found` → offer `/gsd:plan-phase {phase} --gaps` (gap-closure plans). — [workflows/execute-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/execute-phase.md) (`verify_phase_goal`)
- Other post-execution gates: code_review_gate (`required="true"`), regression_gate (cross-phase regression), schema_drift_gate (ORM schema pushed without migration → BLOCKED), codebase_drift_gate (non-blocking), post-merge build/test gate. — [workflows/execute-phase.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/execute-phase.md)
- `workflow.node_repair` (default on, budget 2) attempts autonomous repair of failed tasks. — [docs/CONFIGURATION.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/CONFIGURATION.md)

**UAT**
- `/gsd-verify-work`: "Show expected, ask if reality matches" — one test at a time, plain-text answers; persistent UAT.md; on failures spawn parallel debug agents ("Diagnosis runs automatically - no user prompt"), then `gsd-planner` in `gap_closure` mode reading UAT.md, plan-checker verification and revision loop, ending in "present_ready" for `execute-phase --gaps`. — [workflows/verify-work.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/get-shit-done/workflows/verify-work.md)
- Newer: `human_verify_mode: end-of-phase` (default since #3309) suppresses mid-flight `checkpoint:human-verify` tasks and embeds human checks in `<verify>` for end-of-phase review. — [docs/CONFIGURATION.md](https://github.com/gsd-build/get-shit-done/blob/bdcaab2/docs/CONFIGURATION.md)
- Successor: the "honest verifier" abstains (`human_needed`) on non-inferable truths instead of false-passing; an API-coverage gate blocks `/gsd-verify-work` for external integrations without a decided coverage matrix. — [open-gsd/gsd-core docs/whats-new-1.7.0.md](https://github.com/open-gsd/gsd-core/blob/main/docs/whats-new-1.7.0.md)

### Inferences
- GSD verifies at three distinct points (plan, build, human) with different checkers each in their own context, and each loop is bounded; this is closer to "validate" in the user's pipeline than to a single review step.
- The goal-backward vocabulary (truths → artifacts → key_links) is carried from planning into verification via PLAN frontmatter, i.e. the plan itself is the contract for the verifier — plus ROADMAP Success Criteria as an un-reducible floor.

### Gaps
- Did not read the verifier's Steps 7b/7c/8+ in full or `gsd-nyquist-auditor`; Nyquist ("test coverage mapping") described only from docs/config.
- No independent evidence in my sources of how often the plan-checker loop actually catches real defects versus ceremony.

## 5. Weaknesses and criticisms (cost, complexity, ceremony, security, governance)

### Takeaway
The recurring complaint (HN, Reddit, blogs) is that GSD is heavy: high token/limit burn, hours instead of minutes for what Plan Mode does quickly, many files and a waterfall feel; supporters say it pays off on large/complex, multi-session, greenfield work. GSD's own docs concede several of the costs. Separately, the project has a governance crisis (maintainer unreachable since 2026-04-01, repo archived and migrated).

## 6. Recent changes in 2026 and multi-runtime support

### Takeaway
Through spring 2026 GSD grew from a Claude Code tool to a 15+-runtime installer (Claude Code, Codex, Gemini CLI, OpenCode, Kilo, Copilot, Antigravity, Cursor, Windsurf, Augment, Trae, Qwen, Hermes, CodeBuddy, Cline) and added many gates and cost levers (v1.39–1.42, May 2026). The original repo then went dormant (last commit 2026-05-31) and the project continues as **GSD Core** (`open-gsd/gsd-core`, npm `@opengsd/gsd-core`), which by 2026-11-06 is at 1.20.1 with a formal host-integration interface, capability plugins, and 18 installable runtimes (Gemini CLI removed after Google discontinued it).

### Inferences
- The "current" GSD for any late-2026 comparison should be treated as GSD Core 1.20.x; versions quoted in older blogs/HN (1.2x–1.4x of `get-shit-done-cc`) map to the earlier line. Command names/files remain recognizably the same (`commands/gsd/*`, `agents/gsd-*`), so findings above generalize, but file counts and flags (e.g., `/gsd-onboard`, `quick-batch`, `next`, mempalace commands, `*.compact.md` agents) have shifted.
